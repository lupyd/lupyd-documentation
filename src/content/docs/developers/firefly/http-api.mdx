Base URL: `https://firefly.lupyd.com`. Bodies are protobuf messages from
`package firefly` (`crates/protos/protobufs/message.proto` in the
[`firefly`](https://github.com/lupyd/firefly) repository) unless noted. Protobuf
responses set `Content-Type: application/x-protobuf; proto=firefly.<Message>`.

Unless marked otherwise, every endpoint requires
`Authorization: Bearer <access-token>` (see [Authentication](/developers/firefly/authentication/)).

<Aside type="tip">
	Most clients never call these endpoints directly — the
	[client SDK](/developers/firefly/client-sdk/) does. This reference is for people
	building or debugging a client.
</Aside>

## Conventions

- **List parameters** are separated by `%2C` (a percent-encoded comma). Query values are
  not otherwise URL-decoded.
- **Write endpoints** return `200` with an empty body unless a response is listed.
- **Errors** are plain text:

| Status | Meaning |
| --- | --- |
| `400` | Missing or invalid parameter, or an MLS validation failure (for example a stale commit). |
| `401` | Invalid token or missing permission. |
| `403` | Not allowed — not a group member, insufficient group permission, or plan limit reached. |
| `404` | Not found, or unknown path. |
| `405` | Method not allowed on this path. |
| `408` | Request exceeded the server timeout (30 seconds by default). |
| `409` | Conflict — for example a snapshot head changed or a re-add was already claimed. |
| `413` | Body exceeds the endpoint's limit. |
| `429` | Too many requests for this resource. |

## Message requests

Control who may message and call you. An admin variant with `me=<username>` exists for
server-to-server use.

| Method and path | Body | Response | Notes |
| --- | --- | --- | --- |
| `GET /user/privacy` | — | `MessageRequestSettings` | |
| `PUT /user/privacy` | `MessageRequestSettings` (1 KiB) | — | Set `requests_disabled`. `POST` is also accepted. |
| `POST /user/accept?other=<username>` | — | — | Accept a user. |
| `DELETE /user/accept?other=<username>` | — | — | Revoke acceptance. |
| `GET /user/accepted` | — | `AcceptedUsers` | |
| `POST /user/accepted` | `AcceptedUsers` (512 KiB) | count (text) | Accept many users at once. |
| `POST /user/block?other=<username>&blocked=true` | — | — | Block or unblock (`blocked=false`). Also accepts a JSON body `{ other, blocked }`. |

Usernames here are 3–30 characters of `A–Z`, `a–z`, `0–9`, or `_`.

### Pinned messages and history snapshots

Encrypted snapshot blobs. The body is ciphertext (`application/octet-stream`); metadata
travels in headers.

| Method and path | Limit | Notes |
| --- | --- | --- |
| `GET /group/pinned/{groupId}` | — | Returns the current snapshot with an `X-Snapshot-Id` header. |
| `POST /group/pinned/{groupId}` | 64 KiB | Headers: `X-Snapshot-Id`, `X-Expected-Snapshot`, `X-Message-Count`. |
| `GET /group/messages_chunk/{groupId}/{id}` | — | `{id}` is 32 hex characters. |
| `POST /group/messages_chunk/{groupId}/{id}` | 200 KiB | Also `X-Start-Id`, `X-End-Id`. |
| `GET /direct-pins/{username}` | — | Pinned messages in a 1:1 conversation. |
| `POST /direct-pins/{username}` | 64 KiB | Also `X-Ciphertext-Sha256` (64 hex characters); `X-Message-Count` 0–50. |

Writes return `stored`. `409` means `X-Expected-Snapshot` no longer matches the current
head — fetch, merge, and retry. Groups are limited to 16 snapshot writes per minute and
256 MiB of snapshot storage (`429` beyond either).

## Encrypted backups

| Method and path | Body | Response | Notes |
| --- | --- | --- | --- |
| `GET /backups/direct` | — | `DirectBackupState` | Current backup state. |
| `GET /backups/direct?id=` | — | protobuf | One backup record. |
